# История разработки CoRFAGen, до версии 1.6.0 — BeGenSt · PDF&Pic2RFA (по чату с Claude, сентябрь–октябрь 2026)

*Русский · [English version below](#english-version)*

## Исходная задача
Открытый плагин ArchSmarter **FamFab** (Revit, семейство по картинке через Claude API):
1. проверить работоспособность — в VS не появлялась вкладка, ошибка **CS0234**;
2. переработать: семейство из **2D векторного PDF-чертежа (≥ 2 вида)**, подключение не только Claude, но и **Gemini**.

## Версии и решения

| Версия | Что сделано |
|---|---|
| 0.x (FamFab fix) | CS0234/System.Text.Json на net48: ссылка System.Net.Http + пакет System.Text.Json; TLS 1.2; резолв сборок из папки надстройки. PDF как вход (Claude document / Gemini inline_data), Gemini-клиент, выбор провайдера. |
| — | Циклон (`TestDrawings/Cyclone_reference.json`): тела вращения для конуса, параллельные плоскости бленд, тангенциальный вход (внутренняя стенка по касательной, наружная — 45° с касательной), опорные лапы ~200 мм только внизу цилиндра, фланец входа 800 мм от оси, высота 860 (цепочка 340+430+90). Причина «пропавшего конуса» — старая DLL (Revit держал файл). |
| 1.0.0 | Переименование: вкладка **BeGenSt**, панель **PDF&Pic2RFA**, кнопки PreGenerate / RFAGen; тёмно-серый UI с оранжевым/жёлтым/белым; до 3 файлов (PDF/JPG/PNG); техданные из PDF → параметры (встроенные Model/Manufacturer/…, типизированные масса/кВт/м³/ч…, текстовые); проверка исходных данных с диалогом конфликтов; проверка модели перед предпросмотром (GeometryInspector + ИИ). MSI на WiX v5 для Revit 2024–2027 (`BuildInstaller.cmd`). Навык `rfagen-json-from-drawing` — JSON без API-ключа. |
| 1.1.0 | Провайдер **DeepSeek** (OpenAI-совместимый). PDF не принимает → локальная растеризация PDF (Docnet.Core/pdfium) + текстовый слой. Итог теста: ~13 элементов против ~30 у Claude/Gemini (картинка ужимается до ~1300 px). |
| — | Анализ альтернатив: `docs/BeGenSt_AI_models_comparison.xlsx` (Qwen, GPT-5.6 Luna, Gemini Flash/Lite, Mistral, GLM…). |
| 1.2.0 | DeepSeek заменён на **Alibaba Qwen** (qwen3.7-plus, страницы PDF 3600 px, до 16 Мп на изображение), поле Base URL (ключи привязаны к региону). |
| 1.2.1 | Модели с «/» в имени идут в **OpenRouter** (`https://openrouter.ai/api/v1`) с отдельным ключом OpenRouter. |
| 1.2.2 | «Missing Authentication header»: очистка ключа от невидимых символов, типизированный заголовок Authorization, диагностика 401 (маска ключа). Бесплатные модели OpenRouter: qwen3.8-27b:free снят, inkling-small:free — только для агент-приложений (не обходим). |
| 1.3.0 | Кнопка **Purge** (неиспользуемые элементы, несколько проходов, сохранение со сжатием — размер файлов уменьшился в 3–4 раза). Галочки: **параметры семейства/шаблона** (язык ru/en определяется автоматически) и **ФОП** (общие параметры из .txt). Новые иконки (тёмно-серый/синий/жёлтый); PreGenerate → **Generate**. Русские опорные плоскости шаблона не удаляются. |
| 1.3.1 | Сопоставление/перевод параметров и для **Load JSON** (ИИ при наличии ключа, иначе словарь); переименование в выражениях. **Тип семейства** = имя семейства из плагина. **Описание** = «Наименование» + технические характеристики. Purge — первая кнопка. |
| 1.4.0 | **TypeGen**: семейство с несколькими типами по таблице каталога (окно TypeGen: чтение таблицы ИИ, редактируемая таблица, фигура/префикс/шаблон имени, один параметрический шаблон, проверка L/H по каждому типу, 3D-предпросмотр типа, Save/Load catalog JSON). Генератор: типы, параметры типа, наборы геометрии с видимостью (BGS_Набор / BGS_Видимость_NN), отверстия «holes» с круговым массивом, переключатель привода «Показать_привод», автоматический Purge. Подстановка параметров в выражениях — по целым идентификаторам. Эталон: клапан КЗРр 25с947нж ГК «Авангард», 40 типов. |
| 1.4.1 | После теста TypeGen: **таблица выбора** BGS_Catalog (CSV, size_lookup по DN+PN с проверкой каждого типа, откат к значениям при несовпадении) + типы на каждую строку; **2 трубных коннектора** (Global) на ±L/2 на скрытых дисках, длина привязана к L, диаметр = DN; категория «Обобщённые модели» → **«Арматура трубопроводов»**, тип детали «Клапан — врезка»; поэлементный круговой массив `pattern`; детализированный эталон клапана (27 элементов: патрубки-конусы, корпус из двух конусов, крышка со шпильками, бугель, привод с двигателем и маховиком); вспомогательные параметры переименованы в ASCII (BGS_Set, BGS_Vis_NN, BGS_Conn_*, BGS_Zero). Замечание: в тесте была установлена 1.3.1 — сборка 1.4.0 не выполнялась. |
| 1.4.2 | TypeGen: полые выдавливания (отверстие корпуса) всех наборов были видны в редакторе семейств, в т.ч. в «Видимости просмотра» — у пустот нет параметра «Видимость». Теперь все пустоты после вырезания скрываются на всех видах семейства (вырезы сохраняются; «Показать скрытые элементы» — увидеть их). |
| 1.4.3 | По отчёту генерации: созданы все 805 элементов (35 × 23 набора; «805/621» — ожидаемое число не учитывало копии массивов, исправлено). Параметры шаблона D2, D3, L, n, d, H были с формулами / только для чтения → значения каталога не записывались, формулы коннекторов и size_lookup отклонялись. Теперь столбцы каталога приводятся к обычным параметрам типа (формула снимается, экземпляр → тип, «отчётный» → обычный, с записью в отчёт); целочисленные столбцы (DN, n) — числовые для size_lookup; запасной вариант коннекторов — значения по типам; в отчёте — текст отклонённой формулы и типы ключей. |
| 1.4.4 | Тест в существующем семействе Avangard.rfa (свои таблицы выбора LTG, ЗРК_Геометрия, РК_Приводы, РК_Регада, параметры экземпляра с size_lookup): ошибки «Не удалось сформировать выдавливание» при смене типа и чужой привод. Теперь: предупреждение перед генерацией в семейство с собственным содержимым (вложенные семейства, таблицы выбора, размеры) с рекомендацией нового семейства; журнал ошибок Revit (FailureLog) с именами созданных элементов в отчёте; таблица выбора и формулы size_lookup — отдельной транзакцией после основной, с вариантами формулы и записью причины отказа; отчёт сохраняется после Purge. **Purge → «Full clean before generation»**: кроме неиспользуемых элементов удаляет собственное содержимое семейства — геометрию, коннекторы, вложенные семейства, размеры, линии, опорные линии и свои опорные плоскости, таблицы выбора и формулы size_lookup (параметры сохраняются); то же предлагается в TypeGen перед генерацией. |
| 1.5.0 | **DWG/DXF как исходный файл** (Generate и TypeGen): `CadDrawingReader` на ACadSharp 3.8.35 (MIT), без AutoCAD и без преобразования в DXF. Модель получает рендер листа PNG и текст с точными данными: подпись и длина по геометрии каждого размера, области (виды) и их масштаб, тексты, окружности, линии. Проверено на 4 чертежах: все читаются, результат на net8 и net48 совпадает; повторное чтение после сохранения в DXF дало те же данные. Навык: инструмент `dwg_extract`, правила для DWG, проверка генерации в Revit на новом документе семейства. Тест: семейство LSQ-150 из JSON, собранного по DWG, в Revit 2024 генератором 1.4.4: 23/23 элемента, 0 ошибок, габариты 666 × 565 × 801,1. Чтение проверено внутри процесса Revit 2024, где чужие надстройки уже загрузили старый System.Memory (ACadSharp просит 4.0.5, загрузчик плагина отдаёт загруженный): работает. Полный путь через AI с API-ключом не проверялся. Чертежи заказчиков в git не добавляются. |
| 1.6.0 | Плагин переименован в **CoRFAGen** (вкладка CoRFAGen, панель Family Generator, кнопка CoRFAGen в предпросмотре, сборка, пространства имён, установщик `CoRFAGen_<версия>.msi`, навык `corfagen-json-from-drawing`). В описаниях указано, что это плагин для Autodesk Revit, добавлено уведомление о товарных знаках. Настройки с ключами копируются из `%AppData%\BeGenSt\RFAGen` в `%AppData%\CoRFAGen`. Установка заменяет прежнюю версию (`UpgradeCode` и `ClientId` те же). Имена `BGS_*` оставлены: они записаны в уже созданных семействах. |
| 1.7.0 | **Русский язык интерфейса** (Settings → Interface language): окна, подсказки, диалоги, ошибки, 3D-просмотр, лента без перезапуска. Механизм `Loc`: английский текст остаётся в коде, перевод готовых строк по словарю и шаблонам. Подписи кнопок и название не переводятся, кроме Settings на ленте. Ответы ИИ для пользователя на русском; запросы и отчёты на английском. Исправлены логотип RFA\|Gen и `size_lookup` на флажке. Предложены 3 набора значков (`docs/icon-variants`). В Revit не запускалась: выпущена как предварительная. |
| 1.7.2 | Значки с оранжевым элементом теперь действительно в плагине: в 1.7.1 сборка для Revit 2024 осталась со старыми картинками, установщик теперь собирается с `--no-incremental`. В настройках первой строкой идёт язык интерфейса, под ней настройки ИИ. |
| 1.7.1 | В русском режиме переведены и подписи всех кнопок (лента, окна, 3D-просмотр), название CoRFAGen остаётся. Новые значки: набор C из `docs/icon-variants`, оттенки синего с оранжевым элементом на каждом значке. |

## English version

### Development history of CoRFAGen, before version 1.6.0 BeGenSt · PDF&Pic2RFA (from the chat with Claude, September–October 2026)

#### Original task
The open-source ArchSmarter **FamFab** add-in (Revit, a family from a picture via the Claude API):
1. check that it works — the tab did not appear in VS, error **CS0234**;
2. rework it: a family from a **2D vector PDF drawing (≥ 2 views)**, support for **Gemini** in addition to Claude.

#### Versions and decisions

| Version | What was done |
|---|---|
| 0.x (FamFab fix) | CS0234/System.Text.Json on net48: System.Net.Http reference + System.Text.Json package; TLS 1.2; assembly resolve from the add-in folder. PDF as input (Claude document / Gemini inline_data), Gemini client, provider selection. |
| — | Cyclone (`TestDrawings/Cyclone_reference.json`): revolutions for the cone, parallel planes for blends, tangential inlet (inner wall tangent, outer wall at 45° to the tangent), support legs ~200 mm only at the bottom of the cylinder, inlet flange 800 mm from the axis, height 860 (chain 340+430+90). Cause of the "missing cone" — an old DLL (Revit held the file). |
| 1.0.0 | Renaming: tab **BeGenSt**, panel **PDF&Pic2RFA**, buttons PreGenerate / RFAGen; dark grey UI with orange/yellow/white; up to 3 files (PDF/JPG/PNG); technical data from PDF → parameters (built-in Model/Manufacturer/…, typed mass/kW/m³/h…, text); source data check with a conflict dialog; model verification before the preview (GeometryInspector + AI). WiX v5 MSI for Revit 2024–2027 (`BuildInstaller.cmd`). Skill `rfagen-json-from-drawing` — JSON without an API key. |
| 1.1.0 | **DeepSeek** provider (OpenAI-compatible). It does not accept PDF → local PDF rasterization (Docnet.Core/pdfium) + text layer. Test result: ~13 elements vs ~30 for Claude/Gemini (the image is downscaled to ~1300 px). |
| — | Analysis of alternatives: `docs/BeGenSt_AI_models_comparison.xlsx` (Qwen, GPT-5.6 Luna, Gemini Flash/Lite, Mistral, GLM…). |
| 1.2.0 | DeepSeek replaced by **Alibaba Qwen** (qwen3.7-plus, PDF pages at 3600 px, up to 16 MP per image), Base URL field (keys are bound to a region). |
| 1.2.1 | Models with "/" in the name go to **OpenRouter** (`https://openrouter.ai/api/v1`) with a separate OpenRouter key. |
| 1.2.2 | "Missing Authentication header": key cleanup from invisible characters, typed Authorization header, 401 diagnostics (masked key). Free OpenRouter models: qwen3.8-27b:free withdrawn, inkling-small:free — for agent apps only (not bypassed). |
| 1.3.0 | **Purge** button (unused elements, several passes, compact save — file size reduced 3–4 times). Checkboxes: **family/template parameters** (ru/en language detected automatically) and **ФОП** (shared parameters from a .txt file). New icons (dark grey/blue/yellow); PreGenerate → **Generate**. Russian reference planes of the template are not deleted. |
| 1.3.1 | Parameter mapping/translation also for **Load JSON** (AI if a key is present, otherwise a dictionary); renaming inside expressions. **Family type** = family name from the add-in. **Description** = "Name" + technical characteristics. Purge is the first button. |
| 1.4.0 | **TypeGen**: a family with many types from a catalog table (TypeGen window: AI reads the table, editable table, figure/prefix/name pattern, one parametric template, L/H check for every type, 3D preview of a type, Save/Load catalog JSON). Generator: types, type parameters, geometry sets with visibility (BGS_Набор / BGS_Видимость_NN), "holes" with a polar array, actuator toggle "Показать_привод" (Show actuator), automatic Purge. Parameter substitution in expressions is by whole identifiers. Reference: Avangard KZRr 25s947nzh valve, 40 types. |
| 1.4.1 | After the TypeGen test: **lookup table** BGS_Catalog (CSV, size_lookup by DN+PN with a check of every type, fallback to values on mismatch) + types for every row; **2 pipe connectors** (Global) at ±L/2 on hidden discs, length bound to L, diameter = DN; category "Generic Models" → **"Pipe Accessories"**, part type "Valve – Insert"; per-element polar array `pattern`; detailed reference valve (27 elements: conical branch pipes, body of two cones, bonnet with studs, yoke, actuator with motor and handwheel); helper parameters renamed to ASCII (BGS_Set, BGS_Vis_NN, BGS_Conn_*, BGS_Zero). Note: 1.3.1 was installed during the test — build 1.4.0 was not run. |
| 1.4.2 | TypeGen: void extrusions (the body opening) of all sets were visible in the Family Editor, including in "Visibility/Graphics" — voids have no "Visible" parameter. Now all voids are hidden in all family views after cutting (cuts are kept; use "Reveal Hidden Elements" to see them). |
| 1.4.3 | Per the generation report: all 805 elements were created (35 × 23 sets; "805/621" — the expected count did not include array copies, fixed). Template parameters D2, D3, L, n, d, H had formulas / were read-only → catalog values were not written, connector and size_lookup formulas were rejected. Now catalog columns are converted to ordinary type parameters (formula removed, instance → type, "reporting" → normal, recorded in the report); integer columns (DN, n) are numeric for size_lookup; connector fallback — per-type values; the report shows the text of a rejected formula and the key types. |
| 1.4.4 | Test in the existing family Avangard.rfa (its own lookup tables LTG, ЗРК_Геометрия, РК_Приводы, РК_Регада, instance parameters with size_lookup): errors "Could not create extrusion" when switching types and a foreign actuator. Now: a warning before generating into a family with its own content (nested families, lookup tables, dimensions) recommending a new family; a Revit error log (FailureLog) with names of created elements in the report; lookup table and size_lookup formulas in a separate transaction after the main one, with formula variants and the rejection reason recorded; the report is saved after Purge. **Purge → "Full clean before generation"**: besides unused elements it removes the family's own content — geometry, connectors, nested families, dimensions, lines, reference lines and its own reference planes, lookup tables and size_lookup formulas (parameters are kept); the same is offered in TypeGen before generation. |
| 1.5.0 | **DWG/DXF as a source file** (Generate and TypeGen): `CadDrawingReader` on ACadSharp 3.8.35 (MIT), without AutoCAD and without conversion to DXF. The model gets a PNG render of the sheet and text with exact data: the label and drawn length of every dimension, regions (views) and their scale, texts, circles, lines. Tested on 4 drawings: all are read, net8 and net48 results are identical; reading again after saving to DXF gave the same data. Skill: `dwg_extract` tool, DWG rules, generation check in Revit on a new family document. Test: family LSQ-150 from a JSON built from the DWG, in Revit 2024 with the 1.4.4 generator: 23/23 elements, 0 errors, overall 666 × 565 × 801.1. Reading was checked inside the Revit 2024 process, where other add-ins had already loaded an older System.Memory (ACadSharp asks for 4.0.5, the add-in resolver returns the loaded one): it works. The full path through the AI with an API key was not tested. Client drawings are not added to git. |
| 1.6.0 | The plug-in is renamed to **CoRFAGen** (tab CoRFAGen, panel Family Generator, CoRFAGen button in the preview, assembly, namespaces, installer `CoRFAGen_<version>.msi`, skill `corfagen-json-from-drawing`). Descriptions state that it is a plug-in for Autodesk Revit, and a trademark notice is added. Settings with keys are copied from `%AppData%\BeGenSt\RFAGen` to `%AppData%\CoRFAGen`. Installing replaces the earlier version (same `UpgradeCode` and `ClientId`). The `BGS_*` names stay: they are stored in families already generated. |
| 1.7.0 | **Russian interface** (Settings → Interface language): windows, tooltips, dialogs, errors, 3D viewer, ribbon without a restart. The `Loc` mechanism: English text stays in the code, finished lines are translated by a dictionary and patterns. Button labels and the name are not translated, except Settings on the ribbon. AI answers for the user come in Russian; requests and reports stay in English. Fixed the RFA\|Gen logo and `size_lookup` on the check box. Proposed 3 icon sets (`docs/icon-variants`). Not run in Revit: released as a pre-release. |
| 1.7.2 | The icons with an orange element are now really in the plug-in: in 1.7.1 the Revit 2024 build kept the old pictures, so the installer now builds with `--no-incremental`. In Settings the interface language comes first, the AI settings below it. |
| 1.7.1 | In Russian, the labels of all buttons are translated too (ribbon, windows, 3D viewer); the name CoRFAGen stays. New icons: set C from `docs/icon-variants`, shades of blue with an orange element on each icon. |

#### Open questions / ideas
* DWG: compare PDF and DWG families through the AI with an API key; check in Revit 2025–2027; real AutoCAD DXF files (the test used DXF written by the same library); unread CYKYDimEntity objects.
* Test 1.3.1: Load JSON + ФОП (Russian) with and without a key.
* Paid OpenRouter models to test: `thinkingmachines/inkling-small`, `qwen/qwen3.8-27b`.
* OpenAI GPT-5.6 Luna (native PDF) — a separate client if a key becomes available.
* Refine in the preview does not yet pass parameter-mapping instructions (names are already in the JSON).
